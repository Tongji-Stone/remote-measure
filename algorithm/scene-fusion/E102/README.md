# E102 保留棋盘格和物体

输入来自 E101 的五组原始扫描、两套光学标定及其 54 个单视角。对原相机坐标中的点使用 150–350 mm 欧氏距离门槛，再用同站盘面标记定位 100×100 mm 棋盘格。棋盘点限制在标称边界内。穿出板缘的棱锥只保留白场轮廓与邻接物体点共同支持的实测部分。

ChArUco 的局部盘面用稳健平面拟合。Chessboard 支路通过相同像素定位实测盘面，再估计低阶深度残差，避免把该支路的光学偏差当作物体高度。残差仅用于判别去留。PLY 保持 E101 的实测坐标，拼接时只施加刚体变换。

| 支路 | E101 有效点 | E102 保留 | 移除比例 |
|---|---:|---:|---:|
| ChArUco | 5,679,367 | 2,679,666 | 52.8% |
| Chessboard | 3,457,826 | 2,256,788 | 34.7% |

每个物品的 `单视角`、`双视角`、`整圈` 文件夹仅含点云 PLY。相同编号的双视角使用 V00、V01 的整圈位姿。各物品的 `结果.json` 保留逐边指标、位姿和回退记录。两个实验共用物体留出集，E102 的棋盘格可参与配准求解。

## 复跑与校验

先按 E101 的说明准备灰码重建、标定和位姿缓存。从仓库根目录依次运行下列脚本。拟合及解码缓存写入临时目录，点云与指标写入 scene-fusion。

1. 用 `algorithm/.venv/bin/python` 运行 `algorithm/scene-fusion/E102/foreground.py`。
2. 对每个支路、五个采集编号运行 `register_crops.py E102 BRANCH SESSION` 和 `register_crops.py E103 BRANCH SESSION`。采集编号为 043648、044244、045127、050019、050554。三种外部求解器的参数为 `--cloudcompare`、`--go-icp`、`--teaser`，详细版本见 E101。Open3D、OpenCV 及局部算法复用 E101。
3. 运行 `validate_masks.py` 和 `verify.py`。前者比较原始白场轮廓，后者检查 PLY 的原始子集、角站点数、双视角截取与刚体位姿。
