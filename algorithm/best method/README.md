# 双相机转台扫描的推荐流程

| 阶段 | 输入 | 输出 |
|---|---|---|
| [01 转台内拼接](01-转台内拼接/README.md) | 一次摆放的灰码、ChArUco 白场、各角站彩照、同期标定 | 在本次 V00 海康坐标中的完整一圈，带板及仅物体两版 |
| [02 跨姿势融合](02-跨姿势融合/README.md) | 同一物体多次摆放的整圈点云，以及各次的单站观测和相机位姿 | 在主摆放 V00 坐标中的融合点云、测点支撑和局部插值标记 |
| [03 E201 曲面重建](03-E201曲面重建/README.md) | 跨姿势融合点云、原始深度、露板测量和标定 | 彩色网格、表面误差、拓扑、体积 |

两级配准都保持刚体尺度。转台内有共同转轴与可追踪的盘面码。物体翻面后进入新的刚体摆放，跨摆放变换允许三轴旋转和平移。毫米尺度始终来自同期相机–投影仪标定。

## 下载后的运行环境

01、02 各自包含核心源码和样例。可把两节目录连同根目录的 [requirements.txt](requirements.txt) 一起上传。案例数据约 27 MB，包含已处理的扫描点与必要的标定。两节的示例均从 JSON 和点云启动。

本机使用 Python 3.14 验证。在本目录创建环境并安装依赖：

```sh
python -m venv .venv
# macOS / Linux
source .venv/bin/activate
# Windows PowerShell 使用 .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

03 曲面重建使用完整项目的原始深度和标定。若单独发布 01、02，可以随两节上传本页和依赖文件，并按发布内容调整索引。

### 随附样例的核验

将 01、02 复制到独立临时目录，用项目 Python 从目录外运行三个清单。南瓜正放选出 R06c，90,118 个点与参考的最近距离 P95 为 0 mm。翻面南瓜用参考位姿得到 38,796 个 B05 点。人偶从点云自动求姿态，得到 91,682 个 B05 点，与 E204 参考点云的最近距离 P95 为 0.235 mm。该距离衡量两次处理输出的几何一致性。

## 本机复跑核验

| 阶段 | 核验输入 | 复跑结果 |
|---|---|---|
| 01 转台内拼接 | 同期原始标定图、十组共 100 站格雷码、南瓜正放 10 站 | 光学标定、彩色配准、灰码解码、R06c、去板和上色完成。南瓜的 E201/E202 整圈 PLY 与归档逐字节一致。独立的单站清单入口也选出 R06c。 |
| 02 跨姿势融合 | E202 南瓜两种摆位、人偶三种摆位，从空 E201 缓存启动 | 重新完成姿态搜索、闭环、F03 实测融合、B05 接缝修复、接缝诊断、留出评估和压力试验。南瓜的 E203/E204 PLY 与归档逐字节一致。人偶 E204 点数同为 91,520，复跑到归档的最大近邻位置差约 0.000015 mm。 |
| 03 曲面重建 | 四个采集对象，S08、S09、G03 合计十组，从空 E201 缓存启动 | 十个彩色网格与归档逐字节一致，体积、面数一致，均通过闭合检查。另从南瓜实测点重新拟合二维高斯盘并提取 G01，留出深度 P95 为 1.78 mm。 |

使用项目内的 Python 环境，复跑保存在临时目录。修复了无缓存时板位姿求解所引起的同名模块导入冲突。现在跨姿势脚本直接调用相机几何模块中的同一判定函数。采集入口验证了参数和模拟转台响应，海康、投影仪与电机联机状态需要在采集设备上实测。
